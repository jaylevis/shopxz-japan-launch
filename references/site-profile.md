# 站点资料与任务范围

`assets/profiles/jp-core.json`是字段契约；`jp-apparel.json`是覆盖层。空值代表未知，不填造经营主体、退货地址、时效或资质。

| 区域 | 来源与用途 | 缺失处理 |
|---|---|---|
| target | 绑定地址、公开域名、shop_id交叉核对 | inspect可发现ID；写入使用已核对的resolved-profile |
| brand | 本站名称、客服邮箱、Logo/favicon路径、电话、品牌色 | 复用真实现值；新图上传后填目标路径 |
| locale | ja、JPY、Asia/Tokyo、JP | 从当前站可选池确认，不能凭示例填不支持值 |
| modules | 本次自动化模块 | 关闭模块无操作；缺权限列出缺口 |
| store_settings | 后台九项的开关、显式覆盖及具体执行方案 | 新资料加载日本预设；旧资料缺此项时不追加后台写入 |
| email | 实际姓名顺序、保留启用状态 | 核对姓/名标签，不从英文变量名推断 |
| marketing | 组合、前缀、次数、期限、叠加、展示、发送节奏 | 商家采用后执行，邮件未就绪时不激活 |
| business / returns | 真实经营与退换条件 | 可完成草稿与独立模块，不能认定可交易上线 |
| shipping | 运费、免邮、处理时间、运输时间、偏远地区 | 发货3–7工作日不写成3–7日送达 |
| integrations | 本站支付、SMTP、GA、Ads、LINE、Clarity | 不挪用参考站账号 |
| storefront / migration | 行业、风格、图片方式、发布意图、旧路径 | 局部修补不重建整站 |

Token、SMTP密码、支付和存储密钥不放profile。业务规则统一供网页、邮件、券与结账使用。

CLI保留系统邮件现有启用状态；强化召回成功切换时才关闭旧type9。个别邮件的启停或经核实的验证码期限，由Agent通过管理技能单独处理。CLI不支持 `email.code_expiry_minutes` 和 `email.notice_enabled_types` 的非空值，会明确拒绝而非忽略。

## 后台设置资料

新生成的profile从 `assets/store-settings.json`加载默认值，`modules.basic=false`关闭整组执行。各项 `apply=false`表示检查后保留，`values`只填本次要改的文档字段。高级设置和验证码默认保留；TASK采用任务结束后刷新缓存。具体含义见 [后台九项设置](store-settings.md)。

- `basic.allow_currency_change`默认false。实际基本币种不同且商家已明确采用JPY时才改为true；需先核对商品金额口径，以及已有多币种应用的汇率基准。
- `payment.enable_codes`是选定支付方式，`credentials_verified_codes`是已经核对账号配置的公开方式代码，`preferred_code`是可选优先方式。都不存账号或密钥。
- `shipping.mode=prepare`使用顶层shipping经营规则准备具体请求；`shipping_id/zone_id`仅用于明确选中的本站对象。未知运费或免邮门槛会留下资料缺口。
- `tax.mode=preserve`保持现状；只有商家提供税率才准备变更。`prices_include_tax`记录商品价格口径，不自动加税或关税。

旧profile没有 `store_settings`时不会自动补进写入规则；需要采用新版时重新生成资料并合并本站已确认事实，不把示例空值覆盖已有值。

## 营销字段（1.3）

- `marketing.payment_deadline_days`：便利店/银行转账付款期限（天，整数4–60）。1.4.1 起预设默认 10（待付款订单不自动取消，期限仅用于提醒节奏与页面口径）；设置后建支付中提醒活动；null则不建。法务页的付款期限须写同一天数。
- `marketing.adopt_activity_id`：接管现有未支付活动的ID（必须恰有4条邮件消息）。null时按工具命名新建。
- `marketing.coupon_codes`：`{"five": "现有券码", "thousand": "现有券码"}`，用现有券代替新建；只校验可用，不改条件。

## 预设含义

服饰399/5000/3–7及5%/1000优惠是可选案例，不是政策。优惠默认每顾客1次、总量0代表不限总量；在方案明确展示。`ends_at=""`不限截止时间，邮件不得虚构倒计时。实际采用的值可以按商家要求改变。

## 模式

- 规划：只读资料并形成方案，不发写请求。
- 对照补缺：检查目标现状；参考站只读。
- 快速上线：按已授权范围持续执行，缺资料只阻断依赖部分。
- 单模块：只做点名模块，不额外发信、改价、清库或发布主题。
- 续跑：复用不可变快照与状态，核对结果，保护商家后续修改。

脚本产物包含已核对资料、快照、具体计划、状态与ID映射、回读和HTML报告。计划中的 `backend_workflows`给出需通过管理技能执行的物流/税费请求与回读；`agent_tasks`另列账号SMTP、政策商品、装修、正式域名和实测。准备了请求不代表已执行，这些缺项不能被自动配置通过掩盖。

## 可移植与可恢复

依赖通过参数、环境或相邻技能发现；无固定盘符。子进程参数数组、UTF-8文件、关闭stdin，避免Windows中文损坏、`&`拆分或GET等输入。检查、状态和快照不得写入技能包。

店铺身份不匹配、权限/版本问题、同名业务冲突、并发修改或写入结果未知，停止受影响分支。无依赖部分可继续。恢复按实际状态判断，不自动重试创建。

打包仅包括通用资源；排除商家快照、订单、凭据、运行状态、浏览器profile和依赖缓存。
