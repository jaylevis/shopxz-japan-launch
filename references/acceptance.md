# 验收与交付

## 证据层次

| 层次 | 证明 | 不能代替 |
|---|---|---|
| 已配置 | 接口值/引用/状态与计划相同 | 页面、收款、投递、官方审核 |
| 已渲染 | 页面/邮件内容与布局 | 后台关联及付款链路 |
| 已交互 | 导航、规格、历史记录、加购 | 订单/支付/退款完成 |
| 业务实测 | 经授权的订单、收件箱或外部账号证据 | 所有未来交易或审核保证 |

本包verify验证其覆盖的配置；Agent结合其他任务与实测给出整站结论。

后台九项（基础、高级、TASK、验证码、支付、交易、税费、国家、物流）各自列当前值、目标值、状态与证据。保留现状要写明；未知、缺资料或待管理技能执行不能算已完成。`backend_workflows.executed=false`仅证明方案已准备。

基础信息回读需含实际语言、币种和时区。若更换基本币种且开启多币种应用，还要核对新基准汇率及前台金额。支付方式已启用不能证明账号已配好或支付已成功；商家确认账号配置和真实交易证据分别记录。

## 上线检查

- 正式域名/HTTPS、关键链接与地图可访问；520恢复记录时间，单次200不证明长期稳定。
- 身份客服、配送、退换退款真实且一致；无占位承诺、soft404政策页。
- 商品/变体/图片/库存/价格正确，统计覆盖范围真实。
- 国家选择、邮编/姓名/电话字段、商品状态校验和取消订单时限符合采用的交易规则；自动取消时限与召回节奏相容。
- 日本物流覆盖、运费门槛和税费在回读与实际结账中核对；4999/5000/5001的规则计算不能代替真实结账。其他国家、省级例外和自定义税费保留正确。
- 电脑/手机布局、导航、筛选、图片、促销残留和浮层经过浏览器检查。
- 浏览两件商品后历史面板正确；下滑固定栏可见，文字匹配动作，匿名加购数量/小计正确。
- 优惠门槛、次数、时限、叠加与展示一致；自动化剪贴板受限时记录限制，不能伪造复制通过。
- 结账入口可能先创建订单（如cart-checkout）。辨认边界，只有测试订单有授权才继续；裸checkout占位金额不是实际运费。
- 支付方式启用；付款/退款按授权实测，未验证部分明示。
- 系统邮件与召回使用本站事实，切换后旧召回停用；投递未测时明确。
- 外部搜索、Feed、统计按所选业务验收，字段存在不等于平台批准。

## 状态

`CONFIGURATION_VERIFIED`：本包覆盖的配置回读通过，适用的后台流程没有尚待执行项。

`CONFIGURATION_INCOMPLETE`：配置未核实或尚有未执行的后台流程；查看各项证据与 `pending_agent_workflows`。自动保存部分通过不改变此口径。

`COMPLETED_WITH_GAPS`：可执行部分完成，尚有经营资料或外部验收缺口。

`READY_TO_LAUNCH`：适用经营、页面、购买链路和发布前验收有证据，附范围。

`PUBLISHED`：已获发布授权的本次主题已成为线上默认，完成发布后回读/前台复查。

缺支付、关键政策或购买路径不可用时不得认定可交易上线。单元测试/模板检查通过不是新站上线证据。

## 发布与回执

先完成具体可审阅预览，再在用户授权范围调用管理技能发布流程。已有授权不重复问；实际API确认挑战按原规则处理。没授权发布则交付预览。

按实际修改刷新缓存，核对公开域名、启用主题与关键页面。迁移检查旧路径和资源域名。

报告给出规则、对象对应信息、测试证据和待办；提供本地HTML与JSON，不强迫用户打开127.0.0.1。保留快照/状态，排除凭据与客户信息。回滚只处理本轮变更，保护后来商家修改。
